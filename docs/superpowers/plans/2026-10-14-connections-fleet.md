- Preserve all existing work, the complete product scope, the agent-first rationale, existing human/API-key authentication, evaluation `Run`/Runner behavior, v1 registry bytes, and executable-v2 wire/signature contracts. Automation Anywhere remains a reference. E03 adds no UI.

- Read `AGENTS.md` and `SECURITY.md`. No production database access, cloud changes, customer communication, public package release, additional PR merge or deployment is authorized by this plan.
- Runtime/enrollment/session tokens contain at least 256 random bits; only token digests are stored server-side. No secret material in URLs, argv, logs, audit, model context or inventory. Private one-time responses carry `Cache-Control: no-store`.
- Enrollment lifetime: ten minutes. Active credential lifetime: fifteen minutes. Begin rotation with at least five minutes remaining and bounded jitter. Pending activation deadline: 60 seconds. Process lease: one minute. Heartbeat: twenty seconds.
- Server/database time supplies expiry decisions. A detected clock disagreement beyond 30 seconds fences authority; it is not additional validity. SDK command lifetime remains at most five minutes, with half-open validity and no grace for future or expired commands.
- Sessions use a separate random 256-bit secret, server-side digest only, held only in supervisor memory. Rotation preserves the generation; takeover after expiry increments it and invalidates old sessions and pending successors. A copied credential alone cannot preempt the current session.
- Every reference/query checks full workspace/project/environment scope. Installation and recovery epoch bind enrollments, credentials, sessions and commands. Current workspace/pool/connection revocation and authority apply independently of immutable pins.
- Terminal replay tombstones survive at least 24 hours and beyond command expiry plus the permitted clock skew. In-progress/uncertain records remain until explicit reconciliation/retention policy. No exactly-once external-effect claim.
- Secrets resolve only inside the worker after current identity/authority, connection and destination checks. API/engine/package/command receive references only. Python memory zeroization and hostile-host isolation are not promised.
- Schema revision 12 advances additively to 13. Preserve existing environment configuration, evaluation and registry data; no automatic connections, authority, enrollment or destructive downgrade.
- Keep SDK distribution 0.2.0 and all SDK public contracts unchanged. Introduce `lotuspond-runtime==0.1.0`; declared, locked and built metadata must agree. No heavy runtime-only dependency may silently enter the API image.
- Implement tasks in order on an isolated implementation worktree after plan review. ### Frozen contract conventions

Task 1 defines the foundational shared types below; later tasks extend this same pure module with their explicitly listed DTOs. Models are frozen, strict, `extra='forbid'`, with bounded safe errors; public helpers revalidate constructed/mutated model instances rather than trusting Pydantic construction. Exact integer fields reject booleans/floats. Canonical UUID strings identify persisted customer records; installation IDs use the existing SDK opaque-ID grammar (1..128 ASCII characters). Recovery epochs and generations are exact integers in 0..9,007,199,254,740,991, matching the SDK; never stringify an epoch. Digests are 64 lowercase hexadecimal characters. Timestamps are nonnegative exact safe-integer UTC milliseconds. Names are 1..160 characters. Arrays reject duplicates where they represent sets; canonical ordering uses string order for operations/platforms/connection IDs, `(name, version, artifact_sha256)` for connector pins, `(reference_id, version)` for secret pins and `(host, port, path_prefix)` for destinations, with numeric comparison for integer components. Operation/path rule order has no implicit precedence.

- `Scope(workspace_id: str, project_id: str, environment_id: str)`; every component is a canonical UUID.
- `ConnectorPin(name: str, version: str, artifact_sha256: str)`; name uses the existing SDK `Identifier` grammar (`^[a-z][a-z0-9]*(?:[-_][a-z0-9]+)*$`, at most 64 characters), version uses its three-component `Version` grammar (each component 0..999999, no leading zeros, at most 20 characters). Operation names use `Identifier` too. `SecretPin(reference_id: str, version: int)` uses a UUID and integer 1..2^31-1.
- `DestinationRule(host: str, port: int, path_prefix: str)` bounds host to 253 ASCII bytes and path_prefix to 1024 UTF-8 bytes; it uses a lowercase ASCII DNS name without trailing dot or a canonical IP literal, port 1..65535, and an absolute normalized path prefix with segment-boundary matching. IDNA conversion is not implicit; a customer requiring international names supplies reviewed ASCII form. Task 7 owns the normalization/refusal algorithm.
- `ConnectionConfig(format_version=1, connector: ConnectorPin, operations: tuple[str,...], destinations: tuple[DestinationRule,...], secrets: tuple[SecretPin,...], data_handling: DataHandling)`; operations 1..32, destinations 0..16, secrets 0..16. `DataHandling(retain_payloads: Literal[False]=False, max_request_bytes: int=65536, max_response_bytes: int=1048576, timeout_ms: int=10000)` allows only bounds 1..65536, 1..1048576 and 1..30000 respectively. Destination-free operations require catalog permission, not an empty-list bypass.
- `PoolPolicy(format_version=1, connectors: tuple[ConnectorPin,...], platforms: tuple[Literal['linux'],...], connection_ids: tuple[str,...], max_instances: int, max_concurrent_invocations: int)`; connectors and connections at most 64 each, platforms exactly `('linux',)`, max_instances 1..1000, max_concurrent_invocations 1..32. These are safety bounds, not license entitlements. Empty allowlists grant no capability.
- `RuntimeObservation(platform: Literal['linux'], connectors: tuple[ConnectorPin,...])` has at most 64 unique connectors. It is a declaration, not attestation. Effective support intersects installed fixed catalog, enrollment ceiling, current pool policy and work requirements.
- `RuntimeIdentity(scope: Scope, installation_id: str, recovery_epoch: int, pool_id: str, instance_id: str, credential_version: int, generation: int)` is safe metadata, never proof. `SelfState(identity: RuntimeIdentity, credential_expires_at_ms: int, session_expires_at_ms: int | None, server_time_ms: int)` reveals no digest, token, session ID or other worker's state.
- `IssuedCredential(token: SecretStr, state: SelfState)`; `PreparedCredential(token: SecretStr, credential_version: int, activation_deadline_ms: int, server_time_ms: int)`; `AcquiredSession(secret: SecretStr, identity: RuntimeIdentity, expires_at_ms: int, server_time_ms: int)`. Explicit one-time response encoders unwrap only the intended secret; ordinary repr/model JSON never does. `CredentialState(format_version=1, revision: int, instance_id: str, active_token: SecretStr, pending_token: SecretStr | None, pending_version: int | None)` is a private local format, never an API response; all-or-none pending fields.
- `FleetError(code: str)` restricts codes to `invalid_request`, `input_limit`, `unauthenticated`, `forbidden`, `not_found`, `conflict`, `rate_limited`, `authority_unavailable`, `unsafe_storage`, `transport_failed`, `destination_denied`, `secret_unavailable`, `trust_unavailable`, `command_rejected`. No input/path/URL/provider body is embedded in its message.

Fleet JSON input is at most 65,536 raw bytes, depth 16 and 4,096 total values/member names, with at most 8,192 UTF-8 bytes per free string before field-specific validation. Reject duplicate keys, nonfinite numbers, invalid Unicode, cycles, unknown fields and coercions before canonicalization. A connection/pool canonical document is at most 32,768 bytes. Use rfc8785, not SDK private helpers. Connection digest is SHA256 of `b'lotuspond-connection-config-v1\0' + canonical_config`; pool digest uses `b'lotuspond-runtime-pool-policy-v1\0'`. Freeze literal canonical-byte/digest fixtures and independent Node SHA256 checks. Do not hash secret values.

Frozen canonical fixtures (UTF-8, no trailing newline inside the digest) use an explicit synthetic artifact digest; this digest is valid protocol data and does not register an installed connector. The connection fixture is exactly 336 bytes, digest `b986684ecd1f4fca794d3ad8dfc808ebabcc311f256992de86dabc6e0cb768e8` under the connection domain:

```json
{"connector":{"artifact_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","name":"lotuspond-fixture","version":"1.0.0"},"data_handling":{"max_request_bytes":65536,"max_response_bytes":1048576,"retain_payloads":false,"timeout_ms":10000},"destinations":[],"format_version":1,"operations":["inspect"],"secrets":[]}
```

The pool fixture is exactly 258 bytes, digest `ad5efd0394a447567a58c2c9df3f8febcf2ebe69d36e7ee6e57a9af36c3d65dd` under the pool domain:

### Routes, safe results and error behavior

Management prefix `M = /api/v1/projects/{project_id}/environments/{environment_id}`; workspace comes only from the authenticated browser session. Initially every E03 management read/write requires an eligible customer owner/admin session through existing verification/MFA checks. API keys, runtime tokens and platform operators without customer membership fail. List endpoints use keyset `after_id` and `limit` 1..100 (default 50), scoped to the selected collection; no offset/full-table counts.

- `M/connections`: POST create, GET list; `/{connection_id}` GET; `/{connection_id}/status` POST active/disabled/revoked; `/{connection_id}/versions` POST immutable config, GET metadata list; `/{connection_id}/versions/{version}` GET explicit permitted config and digest.
- `M/secret-references`: POST `{binding_id, version}` metadata, GET list; `/{reference_id}/revoke` POST. Binding IDs are opaque operator catalog IDs, never paths/cloud resource identifiers. Revocation is terminal.
- `M/runtime-pools`: POST create, GET list; `/{pool_id}` GET; `/{pool_id}/status` POST; `/{pool_id}/policies` POST immutable policy, GET metadata list. Policy publication selects that new current revision atomically; historical revisions remain.
- `M/runtime-pools/{pool_id}/enrollments`: POST one-use issuance and GET safe inventory; `/{enrollment_id}/revoke` POST. Request contains an observation ceiling; server intersects it with the current pool. Response contains enrollment ID, expiry and token only on initial issuance.
- `M/runtime-instances`: GET list; `/{instance_id}` GET; `/{instance_id}/revoke` POST. Responses expose IDs/status/current policy/generation and observed timestamps; no credential/session hashes, false health score or secret metadata from another scope.

Runtime prefix `R = /api/v1/runtime`: POST `/enroll`, GET `/self`, POST `/session`, POST `/heartbeat`, POST `/credentials/prepare`, POST `/credentials/activate`, POST `/credentials/cancel`, POST `/commands/poll`, POST `/commands/{command_id}/claim`. No public submit/sign/dispatch or connector-invocation endpoint. Poll returns at most one eligible command or null; no long polling in E03. Claim is an internal admission claim, never authorization to perform a business effect by itself.

Use `Authorization: Bearer <token>` and, where required, `X-Lotuspond-Runtime-Session: <secret>`. Reject duplicate authentication/session/workspace headers, comma-concatenated tokens and unexpected token types before service calls. No URL/body credential fallbacks. Fleet requests allow only identity encoding and JSON mutations. Add route-specific body/header checks without changing other endpoints' established behavior. HTTP mapping: 400 invalid request; 401 unauthenticated (including expired/revoked/unknown credential); 403 forbidden; 404 scoped not found; 409 conflict; 413 input limit; 429 rate limited; 503 unavailable authority/storage/trust dependencies. Internal error detail never reaches clients.

Non-secret-returning management mutations require `Idempotency-Key` (1..128 SDK opaque-ID characters), scoped by workspace/project/environment, operation and canonical request digest. Same key/content returns the existing safe result after current authorization; changed content conflicts. Enrollment/session/credential issuance follows the explicit one-time protocols instead. List/config responses are no-store. Secret/destination configuration may be visible to the authorized administrator but never enters audit, list summaries or public errors.
